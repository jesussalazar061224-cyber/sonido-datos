1. Idea general

Es un sistema de comunicación digital donde el canal es el aire: el altavoz es el transmisor y el micrófono el receptor. Se usa MFSK (Multiple Frequency-Shift Keying): cada símbolo se representa con un tono de frecuencia distinta.

2. Codificación (fuente → bits → símbolos)

  1. El texto se convierte a bytes con UTF-8 (así funcionan la ñ, acentos y emojis).
  2. Se arma una trama: [LONGITUD][DATOS…][CRC-8].
  3. Cada byte se divide en 2 nibbles (4 bits → valor 0–15). Cada nibble = 1 tono ⇒ 4 bits por símbolo.
  4. Los nibbles alternan entre el banco A y el banco B de frecuencias. Así dos símbolos seguidos nunca tienen el mismo tono y el receptor puede separarlos sin necesitar un reloj sincronizado (por ejemplo, la letra “3” = 0x33 serían dos tonos iguales seguidos).
  5. La transmisión empieza con un tono de INICIO (más largo, sirve de preámbulo) y termina con un tono de FIN.

3. Plan de frecuencias

Separación de 75 Hz, rango 1200–3675 Hz: es la zona donde altavoces y micrófonos de celulares responden mejor.

4. Demodulación (receptor)

  1. Se capturan muestras del micrófono (sin cancelación de eco ni supresión de ruido).
  2. Se toman ventanas de ~43 ms (con ventana de Hann y 50 % de traslape).
  3. En cada ventana se aplica el algoritmo de Goertzel a las 34 frecuencias (es como una DFT pero solo en las frecuencias que interesan, muy eficiente).
  4. Si la frecuencia más fuerte supera el umbral de tonalidad (energía en ese tono / energía total) se toma como símbolo detectado.
  5. Un filtro de “longitud de corrida” exige que el tono aparezca en ≥2 ventanas seguidas para descartar ruido.
  6. Al llegar el tono FIN se reconstruyen los bytes y se verifica el CRC-8 (polinomio 0x07): ✓ si llegó íntegro, ✗ si hubo errores.

5. Tasa de datos

Tasa de bits = bits por símbolo / duración del símbolo. Con 120 ms: 4 / 0.12 ≈ 33 bit/s. Es un compromiso clásico: más rápido ⇒ más errores por eco y ruido.

6. Cómo probarlo

  • Abre esta página en dos dispositivos: uno en “Transmitir” y otro en “Recibir”.
  • El micrófono necesita que la página se abra en Chrome/Edge/Firefox como archivo local o desde una dirección https (por ejemplo, subiéndola gratis a GitHub Pages o Netlify Drop).
  • Alternativa sin micrófono en vivo: graba el sonido con la grabadora del celular y usa “Decodificar archivo de audio”, o descarga el WAV y súbelo.
  • Empieza con el volumen alto, a 30–50 cm de distancia, en modo “Normal”.

7. Ideas para ampliar el proyecto

  • Medir la tasa de error (BER) vs. distancia y velocidad y graficarla.
  • Agregar corrección de errores (Hamming(7,4) o Reed-Solomon).
  • Usar frecuencias ultrasónicas (17–20 kHz) para que sea casi inaudible.
  • Implementar el receptor en Arduino/ESP32 con un micrófono MAX9814.
